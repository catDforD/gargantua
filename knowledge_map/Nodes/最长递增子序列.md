# 最长递增子序列

> 最长递增子序列（LIS，LeetCode 300，Medium）指给定整数数组 `nums`，在不改变其余元素相对顺序的前提下删除若干元素，所能得到的最长**严格**递增序列的长度；求的是子序列而非子串，且默认严格递增。

## 展开

- 题面与约束（LeetCode 官方页）：`[10,9,2,5,3,7,101,18]` → 4（`[2,3,7,101]`）；`[0,1,0,3,2,3]` → 4；`[7,7,7,7,7,7,7]` → 1。`1 <= nums.length <= 2500`，`-10^4 <= nums[i] <= 10^4`。官方进阶要求：*Can you come up with an algorithm that runs in O(n log(n)) time complexity?*
- 官方 topic tags：Array、Binary Search、Dynamic Programming、Longest Increasing Subsequence——官方即以「DP + 二分」两条路线标注。
- **O(n²) 动态规划**：令 `d[i]` 为以 `a[i]` 结尾的 LIS 长度，递推 `d[i] = max(1, max{ d[j] + 1 : j < i 且 a[j] < a[i] })`，答案为 `max(d[i])`。时间 O(n²)、空间 O(n)；若要还原具体序列，需额外前驱数组 `p[]`（空间仍 O(n)）。
- **O(n log n) 贪心 + 二分**：改定义 `d[l]` 为长度 `l` 的递增子序列的**最小可能结尾元素**。两条关键性质：(1) `d` 恒严格有序（`d[l-1] < d[l]`）；(2) 每个 `a[i]` 至多更新一个 `d[l]`。因此定位可以二分：越界则 `push_back`，否则覆盖该位置，答案即 `d.size()`。时间 O(n log n)、空间 O(n)。
- **易错点（来源内部矛盾，已核实）**：cp-algorithms 正文写「找第一个**严格大于** `a[i]` 的数」（`upper_bound` 语义），但紧随其后的代码用的是 `lower_bound`。代码正确、散文有误：严格递增 LIS 必须找「第一个 ≥ x」的位置。反例 `d=[-∞,3,4,6]`、`x=4`：`lower_bound` 得 l=2（把 `d[2]` 覆盖为 4，正确）；按散文的 `upper_bound` 得 l=3，会写出 `d[2]=4, d[3]=4`，破坏严格递增不变式。推论：只有题目改为「非递减」时才用 `upper_bound`。
- 未核验、不写入事实的内容：patience sorting（耐心排序）术语及 Schensted / Aldous–Diaconis 溯源未取到一手来源（Wikipedia 在本环境不可达），LeetCode 官方题解正文需登录才能读取。表述统一采用无争议的「贪心 + 二分」。
