# 混合检索

> 同一次查询并行执行多路互补召回（如 BM25 加向量），再把多份排名融合成一个结果列表。

## 要解决的问题

单一检索信号有盲区。稠密向量擅长语义理解，稀疏向量 / BM25 擅长精确词匹配。把两者结合，用 Qdrant 文档的话说是 *the best of both worlds*。

## 怎么做

- **并行召回**：同一个查询分别走词法检索和语义检索
- **基于排名融合（RRF）**：只看名次不看原始分数，`score(d) = Σ 1/(k + rank(d))`。各路相关性指标不必可比，也不需要调参。原始出处是 Cormack、Clarke 与 Büttcher（SIGIR 2009），k=60
- **基于分数融合**：先把各路分数归一化到同一量纲，再加权合并。OpenSearch 用 `min_max` 归一化加 `arithmetic_mean` 组合（如权重 `[0.3, 0.7]`）；Weaviate 用 `alpha`（1 为纯向量、0 为纯关键词），v1.24 起默认 Relative Score Fusion；Elasticsearch 另有 `linear` retriever

## 优势与代价

- **RRF**：免调参、开箱即用，但丢掉了文档之间的分差
- **分数融合**：保留分差、可以精细控制，但要先了解各路分数的分布才能调好权重

## 适用场景

- **选 RRF**：想要一套不必先测量各路打分就能工作的配置（OpenSearch 官方的判据）
- **选分数融合**：需要保留分差、需要细粒度的归一化控制

## 实践注意

- **k 不是普适常数**：Elasticsearch 的 `rank_constant` 默认 60、须 ≥1，要求至少两路子检索器、各路等权；Qdrant 的 RRF 带权重，k 默认 2，排名从 0 开始
- **分片陷阱**：Qdrant 多分片集合中，融合只有作为主查询时才跨分片全局合并；放进 `prefetch` 里，每个分片只在本地结果上融合，排名会退化成按分片计算
- **可以继续组合**：Elasticsearch 的 retriever 能嵌套成 retriever 树，混合检索的结果可以再交给重排

## 容易混淆

- **混合检索 vs 多阶段检索**：混合检索是并行多路，[[多阶段检索]] 是串联多级。两者正交，生产系统常同时使用
- **多路召回 vs 多阶段召回**：中文里「多路召回」指并行多路，属于本节点；「多阶段召回」指串联多级，属于多阶段检索。面经里常混用

## 关联

- [[RAG]]：上位概念
- [[多阶段检索]]：正交的另一条改进路线，常见链路是「多路召回 → RRF 融合 → cross-encoder 精排 → 生成」

## 扩展思考

- **BM25 和向量召回怎么混合？** 两路并行召回后融合。分数量纲不可比、又不想调参就用 RRF；需要保留分差就先归一化再加权。
- **为什么用 RRF 而不是加权求和？** 各路分数量纲不可比，RRF 只用名次，免归一化、免调参。
