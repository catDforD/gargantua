# 知识图谱节点模板

节点放在 `Nodes/*.md`。front matter 决定节点在图里的位置和连线，正文决定点开后看到什么。按 `type` / `domain` 选下面五种模板之一。

## 改写规则

- front matter 是图谱结构（连线、别名解析、来源），改写正文时保持原样。确需调整（如 domain 归类）要单独说明理由。
- 正文只重组已有的事实，不补充没有出处的内容。资料不够的小节直接省略，不硬凑。
- 可以按需增加专题小节（如「变体」「增量更新」「实践注意」），放在「关联」之前。
- 统一使用全角中文标点；代码、公式、英文术语内部保留半角。

## 通用写作约定

- 第一个 `>` 引用块是节点卡片的摘要，写成一句话定义，控制在 60 字以内：说它是什么、解决什么，不写「它不是 X」。
- 用自己的话讲清楚，中文为主。英文原文引用每个节点最多一处，只在原话本身就是考点时使用。
- 不写过程性元信息（「已核验」「交叉验证」「按本体规则」「本次只核验到摘要」）。确实需要提醒可信度时，写成一条「注意」。
- 列表项以加粗短语开头：`- **短语**：解释`，一条只讲一件事。
- 数字只保留能回答面试问题的关键值，不堆砌。
- 正文提到库内其他节点时用 `[[节点名]]`。
- 渲染器只支持 `##` / `###` 标题、单层 `-` 列表、段落和行内格式（加粗、斜体、行内代码、链接）。**不要用表格、代码块、有序列表和嵌套列表**，它们在图谱页里会显示错乱。
- `## 参考` 只列 2–4 个最重要的外部链接，最后一条写核验日期；完整来源留在 front matter 的 `sources`。来源只有笔记库内链接（`[[...]]`）时省略这一节。
- 「扩展思考」的答案从正文里提炼，没有对应考点时省略。

## 模板一：概念（`type: concept`，非算法）

适用：Harness、Sandbox、Tool Calling、KV Cache、SSE、WebSocket、Streamable HTTP。

```markdown
# 名称

> 一句话定义。

## 为什么需要

一段话：它要解决的问题，没有它会怎样。

## 核心要点

- **要点**：解释（3–6 条）

## 容易混淆

- **A vs B**：一句话区分

## 关联

- [[节点]]：关系一句话

## 扩展思考

- **问题？** 答题要点。

## 参考

- [标题](url)
- 核验日期：YYYY-MM-DD
```

## 模板二：方法（`type: method`，非算法）

适用：ReAct、Plan-and-Execute、PTC、DPO、PPO、GRPO、LoRA、RAG、混合检索、多阶段检索、GraphRAG。

```markdown
# 名称

> 一句话定义。

## 要解决的问题

一段话：动机，以及之前的做法哪里不够。

## 怎么做

- **步骤或机制**：解释（关键公式用行内代码）

## 优势与代价

- **优势**：…
- **代价**：…

## 适用场景

- **场景**：为什么适合 / 不适合

## 关联

- [[节点]]：关系一句话

## 扩展思考

- **问题？** 答题要点。

## 参考

- [标题](url)
- 核验日期：YYYY-MM-DD
```

## 模板三：工具 / 协议（`type: entity`）

适用：MCP、LangGraph。

```markdown
# 名称

> 一句话定义。

## 定位

一段话：谁做的、处在技术栈哪一层、和相邻层怎么分工。

## 核心组成

- **组件**：作用

## 关键机制

### 机制名

- **要点**：解释

## 实践注意

- **坑**：现象与做法

## 关联

- [[节点]]：关系一句话

## 扩展思考

- **问题？** 答题要点。

## 参考

- [标题](url)
- 核验日期：YYYY-MM-DD
```

## 模板四：算法主题（`domain: algorithm`，`type: concept`）

适用：数组、双指针、动态规划。题目节点通过 `instantiates` 挂到主题上。

```markdown
# 名称

> 一句话定义。

## 核心思想

一段话：这个结构 / 技巧的本质，以及它能把什么复杂度降到什么。

## 常见套路

- **套路名**：做法，例题见 [[题目]]

## 易错点

- **错误**：原因与正确做法

## 本库题目

- [[题目]]：一句话考点

## 参考

- [标题](url)
- 核验日期：YYYY-MM-DD
```

## 模板五：算法题（`domain: algorithm`，`type: method`，带 `attributes.leetcode_id`）

```markdown
# 题名

> LeetCode 题号 · 难度：一句话题意。

## 题意要点

- **输入输出**：…
- **约束**：…
- **示例**：…

## 关键观察

一段话：从题面里看出哪个性质，决定了用什么解法。

## 解法

### 解法一：名称（时间 O(·)，空间 O(·)）

- **步骤**：…

### 解法二：名称（时间 O(·)，空间 O(·)）

- **步骤**：…

## 易错点

- **错误**：原因与正确做法

## 关联

- [[主题或同类题]]：关系一句话

## 参考

- [LeetCode 题号](url)
- 核验日期：YYYY-MM-DD
```
